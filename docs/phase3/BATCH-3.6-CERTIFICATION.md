## 1. Executive Summary & Architectural Position

Phase 3 Batch 3.6 solves **how Charlie safely materializes the appropriate worker modality to perform an already-admitted capability**.

The key architectural distinction:
* **Batch 3.2** determines **WHAT** needs to happen (Dynamic Mission Graph DAG).
* **Batch 3.3** determines **WHO** is leased to execute each node (Worker Fleet & Monotonic Fencing).
* **Batch 3.4** determines **WHO** has empirically demonstrated competence (Empirical Metrology & Reputation).
* **Batch 3.5** determines **WHETHER** the business should do it (Feasibility, Hard Constraints, Regime, & Resource Reservation).
* **Batch 3.6** determines **HOW** to safely materialize and sandbox the appropriate worker modality (API, MCP, Browser, Desktop).
* **Batch 6** determines **WHETHER** the specific consequential action is authorized (Execution Firewall).

```text
REAL WORLD
   ↓
Digital Twin / Verified Telemetry
   ↓
Ambient Responsibility Engine (Batch 3.1)
   ↓
Dynamic Mission Graph (Batch 3.2)
   ↓
Agent Runtime / Fleet Orchestration (Batch 3.3)
   ↓
Empirical Metrology & Reputation (Batch 3.4)
   ↓
Business Constraint Sovereignty & Strategic Optimization (Batch 3.5)
   ↓
UNIVERSAL WORKFORCE FABRIC (Batch 3.6)
   ├── Worker Resolution (Modality Preference & Circuit Health)
   ├── Strict Sandbox Containment (Process, Network, FS Quotas)
   ├── Modality Adapters (API, MCP, Browser, Desktop)
   └── Worker Action Proposal Gateway
         ↓
Runtime Admission Gate
   ↓
Batch 6 Execution Firewall
   ↓
Connector Gateway
   ↓
REAL WORLD / Outcome Ledger
```

### Absolute Invariant: Zero Firewall Bypass
The Universal Business Worker Fabric does **NOT** execute external world changes directly. Consequential actions generated by workers are routed as `ActionProposal` instances through the **Worker Action Proposal Gateway** to the **Batch 6 Execution Firewall**. The Worker Fabric *submits* to Batch 6; it never bypasses the firewall.

## 2. Invariants Formally Enforced

| Invariant | Title | Enforcement Mechanism |
|---|---|---|
| **I16** | **Universal Worker Sovereignty** | A worker cannot execute any consequential action on external systems without obtaining cryptographic approval and authorization from the Batch 6 Execution Firewall. |
| **I16-A** | **Sandbox Containment Isolation** | All workers execute strictly within provisioned OS sandbox boundaries. Violations of memory, CPU, process spawning, filesystem access, or egress immediately quarantine the worker and abort execution. |
| **I16-B** | **Deterministic Modality Resolution** | Modality selection (`Api` > `Mcp` > `Browser` > `Desktop`) is strictly deterministic and lexicographical. Stochastic LLM selection is forbidden. |
| **I16-C** | **Monotonic Lease & Fence Invalidation** | A worker cannot initiate or submit proposals with a stale or mismatched fence token. Reassigned or expired leases fail closed. |
| **I16-D** | **UnknownEffect Reification** | If a worker process crashes, drops connection, or times out during a consequential action attempt, the effect state transitions to `UnknownEffect` until cryptographically reconciled. Node state never masquerades as effect state. |
| **I16-E** | **Circuit Breaker Quarantining** | Consecutive failures exceeding the failure threshold transition the worker to `Degraded` then `CircuitOpen`. Isolation violations immediately trigger `Quarantined`. |
| **I16-F** | **Multi-Tenant Memory & Execution Segregation** | All worker instances, action proposals, sandbox profiles, and state storage are partitioned strictly by `TenantId`. Cross-tenant visibility or execution leakage is cryptographically impossible. |
| **I16-G** | **Autonomy Ceiling Pre-Flight Gating** | A worker's autonomy ceiling (`L0_Observe` to `L5_ExecuteBounded`) must strictly equal or exceed the capability's required autonomy tier. Any shortfall results in immediate pre-flight rejection. |

## 4. Key Architectural Implementations

### A. Domain Contracts (`BusinessModelApp.Core.Domain.Runtime.Workers`)
1. **`WorkerContracts.cs`**:
   - `WorkerModality`: `Api`, `Mcp`, `Browser`, `Desktop`.
   - `WorkerLifecycleState`: `Created`, `Provisioning`, `Ready`, `Running`, `Suspended`, `Completed`, `Failed`, `Terminated`, `ProvisioningFailed`, `FenceRejected`, `SandboxViolation`, `UnknownEffect`.
   - `WorkerDefinition`: Modality, autonomy ceiling, sandboxing profiles, supported capabilities.
   - `WorkerInstance`: Leased worker runtime instance with monotonic fence tokens, process IDs, and tenant partitioning.
   - `WorkerExecutionAttempt`: Detailed execution history with start/completion timestamps, resource metrics, resulting effects, and error details.
2. **`WorkerCapabilityContracts.cs`**:
   - `WorkerResolutionRequest` & `WorkerResolutionDecision`: Deterministic scoring based on modality preference hierarchy, health status, and lexicographical definition ID tie-breaking.
   - `CapabilityWorkerMapping`: Links capabilities to permitted modalities and minimum required autonomy tiers.
3. **`WorkerSandboxContracts.cs`**:
   - `WorkerSandboxProfile`: Resource quotas (RAM, CPU, Timeout, Tokens, Bandwidth), allowed filesystem path prefixes, allowed egress endpoints, shell execution permissions, and child process limits.
   - `WorkerIsolationViolation`: Formal record of isolation violations with timestamps, severity, and violation types (`MemoryExceeded`, `CpuExceeded`, `TimeoutExceeded`, `UnauthorizedChildProcess`, `ShellExecutionDenied`, `UnauthorizedFilesystemWrite`, `PathTraversalDetected`, `RegistryModificationDenied`, `UnauthorizedNetworkEgress`, `RawSocketDenied`, `DisallowedCommand`).
4. **`WorkerHealthContracts.cs`**:
   - `WorkerCircuitState`: `Healthy`, `Degraded`, `CircuitOpen`, `Quarantined`, `Recovering`.
   - `WorkerHealthStatus`: Consecutive failure counts, failure rates, total executions, and last transition timestamps.

### B. Core Interfaces (`BusinessModelApp.Core.Interfaces.Runtime.Workers`)
- `IWorkerStore`: Multi-tenant thread-safe storage for worker definitions, instances, capability mappings, and isolation violations.
- `IWorkerSandboxManager`: Provisioning, monitoring, quota verification, and teardown of worker sandboxes.
- `IWorkerHealthManager`: Circuit breaker state transitions, heartbeat updates, and quarantine policies.
- `IWorkerResolver`: Pure deterministic capability-to-worker modality resolution.
- `IWorkerModalityAdapter`: Unified contract implemented by `ApiWorkerAdapter`, `McpWorkerAdapter`, `BrowserWorkerAdapter`, and `DesktopWorkerAdapter`.
- `IWorkerActionProposalGateway`: Secure gateway routing worker consequential actions to the Execution Firewall.
- `IWorkerRecoveryManager`: Reconciliation protocol for `UnknownEffect` incidents.
- `IWorkerFabric`: Master coordinator orchestrating resolution, provisioning, sandboxed execution, and teardown.

### C. Infrastructure Engines (`BusinessModelApp.Infrastructure.Runtime.Workers`)
- `InMemoryWorkerStore.cs`: Thread-safe, multi-tenant partitioned worker repository.
- `WorkerSandboxManager.cs`: Validates resource consumption against quota profiles and records violations.
- `WorkerHealthManager.cs`: Monitors error rates and triggers circuit breakers or quarantines.
- `WorkerResolver.cs`: Evaluates eligible workers, applies modality hierarchy (`Api` > `Mcp` > `Browser` > `Desktop`), and breaks ties lexicographically.
- `ApiWorkerAdapter.cs`: Dispatches REST/webhook calls; routes consequential actions to the proposal gateway.
- `McpWorkerAdapter.cs`: Manages Model Context Protocol tool calls; enforces schema validation and consequential routing.
- `BrowserWorkerAdapter.cs`: Drives headless browser execution with DOM parsing and proposal emission.
- `DesktopWorkerAdapter.cs`: Governs legacy and RPA workloads under strict default-DENY containment.
- `WorkerActionProposalGateway.cs`: Stores and tracks action proposals pending Batch 6 Firewall authorization.
- `WorkerRecoveryManager.cs`: Reconciles interrupted executions into `EffectSucceeded`, `EffectAborted`, or `UnknownEffect`.
- `WorkerFabric.cs`: Master coordinator managing the end-to-end lifecycle.

### D. Frontend Interface (`new-frontend/src/pages/Settings/WorkerFabric.tsx`)
- High-density tactical UI for inspecting and governing the Universal Worker Fabric.
- Modality tabs: **Overview**, **API Workers**, **MCP Workers**, **Browser Workers**, **Desktop Workers**, **Circuit Breakers & Health**, and **Sandbox Isolation Logs**.
- Real-time circuit breaker controls (Manual Trip, Reset, Quarantine Lift).
- Live visualization of isolation violations, resource quotas, and firewall proposal status.
