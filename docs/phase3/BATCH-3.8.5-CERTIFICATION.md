## 3. Invariant I23 + 16 Subordinate Constitutional Laws (I23-A through I23-P)

Batch 3.8.5 formally codifies and enforces **Invariant I23** and its 16 subordinate constitutional laws:

> **Invariant I23 — Decision Sovereignty:**  
> **Charlie may synthesize, evaluate, rank, and recommend decision candidates, but a decision recommendation must never be mistaken for approval, authorization, or execution.**

| Law Code | Law Title | Operational Contract Requirement | Status |
| :--- | :--- | :--- | :--- |
| **I23** | **Decision Sovereignty** | $\text{Decision} \neq \text{Approval} \neq \text{Execution}$. A candidate is strictly a recommendation, never an approved action. | **ENFORCED** |
| **I23-A** | **Decision $\neq$ Approval** | Charlie cannot approve his own recommendation; approval strictly requires Human / PRG-1 Authority. | **ENFORCED** |
| **I23-B** | **Decision $\neq$ Execution** | The Decision Engine emits ZERO `ExecutionPermit`, dispatches no tasks, mutates no ledgers. | **ENFORCED** |
| **I23-C** | **Multi-Criteria Scoring (MCDA)** | Weighted deterministic scoring across Expected Value, Downside Risk, Reversibility, Time-to-Impact, Complexity, Strategic Fit. | **ENFORCED** |
| **I23-D** | **Reversibility & Regret Metrology** | Reversibility classification: Type 1 (two-way door), Type 2, Type 3 (one-way door) + minimax regret calculation. | **ENFORCED** |
| **I23-E** | **Mandatory Multi-Alternative** | Charlie must never present a single choice. The `DoNothing` baseline and counter-alternatives are mandatory. | **ENFORCED** |
| **I23-F** | **Constraint Hard-Gating** | Decisions violating corporate, legal, headcount, or liquidity constraints cannot be recommended without explicit waiver. | **ENFORCED** |
| **I23-G** | **Confidence & Evidence Decoupling** | Decision confidence bounded: $\text{Conf}_{\text{decision}} \le \min(\text{Conf}_{\text{radar}}, \text{Conf}_{\text{scenario}}, \text{Conf}_{\text{causal}}, \text{Conf}_{\text{forecast}})$. | **ENFORCED** |
| **I23-H** | **Trade-off Disclosure** | Every recommendation must disclose intended positive outcomes alongside modeled negative second-order effects. | **ENFORCED** |
| **I23-I** | **Decision Provenance Linkage** | Bidirectional cryptographic linkage: `Reality -> Causal DAG -> Forecast -> Radar -> Scenario -> Decision`. | **ENFORCED** |
| **I23-J** | **Decision Lifecycle State Machine** | Formal state machine: `Synthesized` $\to$ `Evaluated` $\to$ `Ranked` $\to$ `Recommended` $\to$ `PendingReview` $\to$ `ApprovedByHuman`. | **ENFORCED** |
| **I23-K** | **Multi-Tenant Isolation** | Decision candidates, scoring policies, and rationales strictly partitioned by `TenantId`. | **ENFORCED** |
| **I23-L** | **Deterministic Scoring** | Given identical scenario inputs and policy, candidate rankings are bit-for-bit identical. | **ENFORCED** |
| **I23-M** | **AI Decision Validation** | If LLM proposes a candidate, schema, parameter bounds, and feasibility are deterministically validated. | **ENFORCED** |
| **I23-N** | **Policy Snapshot Immutability** | Snapshots of active `DecisionPolicy` weights and risk tolerance thresholds frozen at evaluation time. | **ENFORCED** |
| **I23-O** | **UNKNOWN Epistemic Propagation** | If underlying drivers have `Unknown` epistemic tier, candidate reflects high epistemic uncertainty and reduced confidence. | **ENFORCED** |
| **I23-P** | **Decision Non-Mutation** | A Decision Recommendation may not mutate Reality, Business Twin, Financial Ledger, Mission State, or Historical Evidence. | **ENFORCED** |
